## tanstack-live/screens: TanStack DB live queries on the tracker: 4 screens to their first answer in a fresh tab, then sync batches without and with the screens open

small
- tanstack-live/indexeddb: idb-default; indexedDBCollectionOptions on createIndexedDB, eager (its only mode), an object store per entity; TanStack BTree indexes on the issue fields the screens filter and sort by; preload() getAll; insert, update and delete with an array = one TanStack transaction = one IndexedDB readwrite transaction
- tanstack-live/kv: idb-default; docstoreCollectionOptions, eager, a collection per entity on openDocStore on openDb, no docstore indexes; TanStack BTree indexes on the issue fields the screens filter and sort by; preload() reads each collection from one view; insert, update and delete with an array = one TanStack transaction = one putMany or deleteMany
- tanstack-live/kv-ondemand: idb-default; docstoreCollectionOptions with syncMode on-demand, a collection per entity on openDocStore on openDb; issues indexed by [projectId, status, updatedAt], [assigneeId, status, updatedAt] and updatedAt, so a screen's where and order read one index range per pinned value; joined rows load by id; a batch's creates = insert, its changes to stored rows = utils.transact (one docstore modifyMany, which reads the rows itself)
- tanstack-live/sqlite: sqlite-full; persistedCollectionOptions with syncMode on-demand on createBrowserWASQLitePersistence (wa-sqlite, OPFSCoopSyncVFS, in a dedicated WebWorker), a collection per entity; createIndex on the issue fields the screens filter and sort by, and on id, which become SQLite expression indexes; a batch's changes to stored rows first hold those rows with a live query on their ids, then insert, update and delete with an array = one TanStack transaction = one SQLite transaction
