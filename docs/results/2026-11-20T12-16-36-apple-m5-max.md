- tanstack-ondemand/kv: idb-default; docstoreCollectionOptions with syncMode on-demand on openDocStore on openDb; one docstore index byOwner on [owner, createdAt]; a live query loads its rows through that index, or by id; writes as in tanstack/kv
- tanstack-ondemand/sqlite: sqlite-full; persistedCollectionOptions with syncMode on-demand on createBrowserWASQLitePersistence (wa-sqlite, OPFSCoopSyncVFS, in a dedicated WebWorker, single-tab coordinator); createIndex on owner, createdAt and id, which become SQLite expression indexes (one expression each, so a page by owner sorts that owner's rows); insert/update with an array = one TanStack transaction = one SQLite transaction
- tanstack-ondemand/sqlite-relaxed: sqlite-off; persistedCollectionOptions with syncMode on-demand on createBrowserWASQLitePersistence (wa-sqlite, OPFSCoopSyncVFS, in a dedicated WebWorker, single-tab coordinator); createIndex on owner, createdAt and id, which become SQLite expression indexes (one expression each, so a page by owner sorts that owner's rows); insert/update with an array = one TanStack transaction = one SQLite transaction; PRAGMA synchronous = OFF, so a commit is atomic but does not wait for the disk, as kv's relaxed IndexedDB commit
