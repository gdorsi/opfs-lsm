# Optimising the Zig LZ4 block codec for wasm32: what the spec, lz4.c, lz4_flex and Zig 0.16 say

Question: the throwaway Zig port of the engine (`lz4Decompress`, `lz4Compress`, `hash4` in `scratchpad/zig-engine/engine.zig`) decodes at parity with lz4_flex but its compressed output is 1.4% larger. Which changes close the ratio gap, which speed up decode, and what do the primary sources actually say?

## Answer in twelve lines

1. The ratio gap is not the hash table. lz4_flex 0.11.6 compresses a sub-64 KB input with a 4096-entry `u16` table indexed by `(seq * 2654435761) >> 16 >> 4`, which is the same 12-bit multiplicative hash and the same table size the Zig port uses (`hashtable.rs` `hash`, `HashTable4KU16::get_at`; `engine.zig` `hash4`).
2. lz4_flex does two things the Zig port does not: it extends every match backwards into the pending literals (`compress.rs` `backtrack_match`), and after a match it inserts the hash of position `cur - 2` into the table (`compress.rs` `compress_internal`). The reference does the same catch-up (`lz4.c` `LZ4_compress_generic_validated`, "Catch up") and inserts `ip-1` and `ip` after each match. [I] Backward extension is the most likely source of most of the 1.4%; the post-match insert is the rest.
3. The reference picks a 13-bit `u16` table (8192 entries) for inputs under 64 KB (`lz4.c` `LZ4_hash4` with `hashLog = LZ4_HASHLOG+1` for `byU16`; `LZ4_compress_fastReset_generic`). [I] That is a cheap experiment that could put the Zig port ahead of lz4_flex, not just at parity.
4. Skip-strength (acceleration) is a speed feature for incompressible data, not a ratio feature: step stays 1 for the first 64 misses in the reference (`LZ4_skipTrigger = 6`) and 32 in lz4_flex (`INCREASE_STEPSIZE_BITSHIFT = 5`). [I] Adding it will not shrink output; it may grow it slightly on hard data.
5. Lazy matching appears in none of the fast paths read (lz4.c fast path, lz4_flex, five Zig ports). It is an HC-tier technique. [I] Not worth it for a codec that must stay at lz4_flex decode speed.
6. The Zig decoder copies literals with a runtime-length `@memcpy`, which compiles to one `memory.copy` instruction per sequence, and copies overlapping matches one byte at a time (`engine.zig` `lz4Decompress`; probe (run) in section 4.3). lz4_flex's safe decoder and lz4.c's safe loop both hoist the bounds checks once per sequence and then copy a fixed 16 bytes of literals and a fixed 18 bytes of match when the token fits and there is slack (`decompress_safe.rs` `decompress_internal`; `lz4.c` the "two-stage shortcut").
7. For overlapping matches, lz4.c's safe loop uses `LZ4_memcpy_using_offset_base`: for `offset < 8` it copies four bytes, then four more from `srcPtr + inc32table[offset]`, then rewinds `srcPtr` by `dec64table[offset]`, after which the source is at least 8 bytes behind and an 8-byte wildcopy finishes. lz4_flex's safe decoder only special-cases `offset == 1` (`extend_with_fill`) and otherwise loops byte by byte (`sink.rs` `extend_from_within_overlapping`).
8. Zig 0.16: `std.Target.wasm.cpu.generic` has `bulk_memory` but not `simd128`; `-mcpu=generic+simd128` is accepted and `--show-builtin` lists `simd128` (run). A comptime-length `@memcpy` of 8 or 16 bytes compiles to `i64.load/store` pairs, or `v128.load/store` under `simd128`; a runtime-length `@memcpy` compiles to `memory.copy` behind a zero-length branch; `std.mem.readInt(u32/u64)` compiles to a single `i32.load`/`i64.load` with alignment hint 0 (run, section 4.3).
9. `std.heap.wasm_allocator` is `BrkAllocator`: `alloc` rounds `len + 8` up to a power of two, so the decoder's 4096-byte output lands in the 8192-byte slot class; frees go on a per-class free list, so the second block's allocation is a pop (`BrkAllocator.zig` `alloc`, `free`). Over-allocating the output by a 64-byte wild margin is therefore free.
10. The spec guarantees a decoder: last sequence is literals only, last 5 bytes are literals, last match starts at least 12 bytes before the end, offsets are 1..65535 and 0 is corrupt, and a decoder may reject blocks that break these (`lz4_Block_format.md`, "End of block conditions"). Both lz4.c and lz4_flex turn these into "copy 18 wild bytes if `op <= oend - 32`" style checks.
11. Of the Zig LZ4 repositories on GitHub, jedisct1/zig-lz4 is an API-level port of lz4.c with acceleration but without catch-up, muhammad-fiaz/lz4.zig has catch-up, the `ip-2` insert and an `offset == 1` memset path, lateleite/lz4u has a 14-bit table and catch-up with a byte loop decoder, morgangallant/lz4 is a 4096-entry learning port. None uses `@Vector`, none implements the `inc32table`/`dec64table` overlap copy, none uses a `u16` table (section 4.4).
12. Order of work: (a) catch-up, (b) post-match insert, (c) 13-bit `u16` table, then for decode (d) hoisted-check shortcut with fixed 16/18-byte copies into an over-allocated buffer, (e) `LZ4_memcpy_using_offset_base` for `offset < 8`, (f) only then try `simd128` 16-byte copies, since lz4.c itself says wide copies on wasm are faster on Apple silicon and slower on x86-64 (`lz4.c` comment above `LZ4_WILDCOPY64`).

## 1. The Zig port as it stands

[R] `engine.zig` `lz4Decompress` (lines 111 to 164): per sequence it reads the token, reads an escaped literal length, checks `i + lit > src.len or o + lit > size`, copies literals with `@memcpy(out[o..o+lit], src[i..i+lit])` (runtime length), reads the 16-bit offset, rejects `off == 0 or off > o`, reads an escaped match length, checks `o + ml > size`, then copies the match with `@memcpy` when `off >= ml` and with a `while (k < ml)` byte loop otherwise. Every sequence pays every check. The output is `A.alloc(u8, size)` per call.

[R] `engine.zig` `hash4` (166 to 169): `(readInt(u32, little) *% 2654435761) >> 20`, a 12-bit index. `lz4Compress` (171 to 207): `var table: [4096]u32` memset to `0xffffffff` per call (16 KB), `mflimit = len - 12`, `matchlimit = len - 5`, greedy search with step 1, candidate accepted when `i - cand <= 0xffff` and the 4 bytes match, match extended forwards one byte at a time, no backward extension, no insert inside or after the match beyond the normal insert at the next loop iteration, output through `std.array_list.Managed(u8)` with `append` per byte and `appendSlice` for literals.

[R] The Rust side being compared against: `crates/engine-core/src/sst.rs:263` calls `lz4_flex::block::compress(&blob)` per block; `crates/engine-wasm/src/lib.rs:49` calls `lz4_flex::block::decompress(src, size)`. `crates/engine-core/Cargo.toml:9` enables `safe-encode` and `safe-decode`; `crates/engine-wasm/Cargo.toml:13` enables `safe-decode`. With `safe-decode` on, `block/mod.rs:21-25` aliases `decompress_safe` as `decompress`, so the Rust decoder measured is `decompress_safe.rs`.

## 2. The block format: what a decoder may assume

All [E spec] unless marked.

- A sequence is a token, optional literal-length bytes, literals, a 2-byte little-endian offset, optional match-length bytes. Literal length field 15 means more bytes follow, each 0..255 added, 255 meaning "read another". Match length field is `minmatch` 4 plus the field, 15 meaning more bytes follow ("Compressed block format").
- Offsets: "The maximum `offset` value is 65535. 65536 and beyond cannot be coded. Note that 0 is an invalid `offset` value. The presence of a 0 `offset` value denotes an invalid (corrupted) block."
- Overlap is by definition byte-serial: "Match bytes are copied one at a time, in increasing order, so `matchlength` may exceed `offset`: bytes just copied are copied again."
- End of block, verbatim rules: (1) "The last sequence contains only literals. The block ends right after the literals (no `offset` field)." and its match-length nibble is unused ("encoders should set them to 0, and decoders ignore them"). (2) "The last 5 bytes of input are always literals. Therefore, the last sequence contains at least 5 bytes", with the special case that an input shorter than 5 bytes is one all-literal sequence and the empty input is a single zero byte. (3) "The last match must start at least 12 bytes before the end of block", hence "blocks < 12 bytes cannot be compressed. And as an extension, _independent_ blocks < 13 bytes cannot be compressed".
- Enforcement is permitted, not required: "When a block does not respect these end conditions, a conformant decoder is allowed to reject the block as incorrect. These rules are in place to ensure compatibility with a wide range of historical decoders which rely on these conditions for their speed-oriented design."
- Metadata is out of band: "a decoder will require the compressed block's size, and an upper bound of decompressed size", and databases "must store the size of their compressed block for indexing" ("Implementation notes", "Metadata"). [R] The engine's u32 size prefix (`sst.rs:262`, `engine.zig` `unpackBlock`) is that channel.
- Length registers: with 32-bit length fields overflow "requires a compressed block of size > 16 MB", so implementations that never see such blocks "are safe" ("Large lengths"). [I] The engine's blocks are about 4 KB, so `usize` on wasm32 needs no overflow check on the accumulators.
- Safe decoding: check copies against both buffers, check that `position - offset` does not reach before the start of the buffer ("Such a situation can happen during the first 64 KB of decoded data"), do not blindly decode offset 0 ("the reference LZ4 decoder clears the match segment with `0` bytes"), and handle overlap "with special care. A common case is an offset of 1, meaning the last byte is repeated `matchlength` times." ("Safe decoding").
- The compressor is unconstrained: "The format makes no assumption nor limits to the way a compressor searches and selects matches" ("Compression techniques").

## 3. The reference implementation, lz4.c (branch dev)

### 3.1 Table size and type per input size

- [E lz4h] `LZ4_MEMORY_USAGE_DEFAULT 14`, `LZ4_HASHLOG (LZ4_MEMORY_USAGE-2)` = 12, `LZ4_HASHTABLESIZE (1 << LZ4_MEMORY_USAGE)` = 16 KB, `LZ4_HASH_SIZE_U32 (1 << LZ4_HASHLOG)` = 4096 (`lz4.h:161-168, 712-714`).
- [E lz4c] `typedef enum { clearedTable = 0, byPtr, byU32, byU16 } tableType_t;` and `LZ4_64Klimit = ((64 KB) + (MFLIMIT-1))`. `LZ4_compress_fastReset_generic`: `if (srcSize < LZ4_64Klimit) { LZ4_prepareTable(ctx, srcSize, byU16); ... LZ4_compress_generic(..., byU16, noDict, ...) } else { tableType = LZ4_largeInputTableType(src); ... }`, where `LZ4_largeInputTableType` returns `byPtr` on 32-bit pointers and `byU32` otherwise. `LZ4_compress_default` calls `LZ4_compress_fast(..., 1)` which calls `LZ4_compress_fast_extState`, which calls `LZ4_compress_fast_extState_fastReset`. So a 4 KB block goes through `byU16`.
- [E lz4c] `LZ4_hash4`: `hashLog = (tableType == byU16) ? LZ4_HASHLOG+1 : LZ4_HASHLOG; return ((sequence * 2654435761U) >> ((MINMATCH*8)-hashLog));`. For `byU16` that is 13 bits: 8192 entries of `u16` in the same 16 KB. `LZ4_putIndexOnHash` for `byU16` asserts `idx < 65536` and stores `(U16)idx`.
- [E lz4c] `LZ4_hash5`: used only when `sizeof(reg_t)==8 && tableType != byU16` (`LZ4_hashPosition`), with `prime5bytes = 889523592379ULL` on little-endian: `(U32)(((sequence << 24) * prime5bytes) >> (64 - hashLog))`. [I] Irrelevant to the engine: sub-64 KB inputs always take `byU16` and therefore `LZ4_hash4`.
- [E lz4c] `LZ4_prepareTable`: the table is cleared (`MEM_INIT(cctx->hashTable, 0, LZ4_HASHTABLESIZE)`) when the type changes, when `byU16` and `currentOffset + inputSize >= 0xFFFF`, or when `inputSize >= LZ4_CLEAR_TABLE_THRESHOLD` where `#define LZ4_CLEAR_TABLE_THRESHOLD (LZ4_HASHTABLESIZE / 16)` = 1024 bytes, with the comment "clearing the table is faster than rejecting its stale entries". Otherwise stale entries are kept and rejected via the `dictSmall` directive. [I] For 4 KB blocks the reference therefore memsets 16 KB per block, the same cost the Zig port pays; a `u16` table halves it.
- [E lz4c] The empty-slot convention: the table is zero-filled and the first position is inserted before the loop (`LZ4_putPosition(ip, ...); ip++;` under "First Byte"), so index 0 is a real entry, not a sentinel. lz4_flex copies this (section 4.1).

### 3.2 The search loop, skip strength, candidate test

- [E lz4c] `static const U32 LZ4_skipTrigger = 6; /* Increase this value ==> compression run slower on incompressible data */` and `#define LZ4_ACCELERATION_DEFAULT 1` (`lz4.h:614`). In the `byU32, byU16` branch of `LZ4_compress_generic_validated`: `int step = 1; int searchMatchNb = acceleration << LZ4_skipTrigger; do { ... ip = forwardIp; forwardIp += step; step = (searchMatchNb++ >> LZ4_skipTrigger); if (unlikely(forwardIp > mflimitPlusOne)) goto _last_literals; ... } while(1);`. With acceleration 1, `searchMatchNb` starts at 64, so `step` is 1 for 64 consecutive misses, 2 for the next 64, and so on.
- [E lz4c] Order of tests, with the reason: "noDict : the candidate is within input, so it is compared before checking its distance : this order is faster (better branch prediction)". The distance test is compiled out entirely for `byU16` when `LZ4_DISTANCE_MAX == LZ4_DISTANCE_ABSOLUTE_MAX` (65535), because a `u16` index cannot be further away than that: `((tableType != byU16) || (LZ4_DISTANCE_MAX < LZ4_DISTANCE_ABSOLUTE_MAX)) && (matchIndex+LZ4_DISTANCE_MAX < current)`.
- [E lz4c] Each probed position is inserted as it is probed: `LZ4_putIndexOnHash(current, h, cctx->hashTable, tableType);` inside the do-while, and the hash of the next position is computed one step ahead (`forwardH = LZ4_hashPosition(forwardIp, tableType);`).

### 3.3 Catch up (backward extension) and match counting

- [E lz4c] Immediately after a candidate passes: `/* Catch up */ ... if ((match > lowLimit) && unlikely(ip[-1] == match[-1])) { do { ip--; match--; } while (((ip > anchor) & (match > lowLimit)) && (unlikely(ip[-1] == match[-1]))); }`. The match grows backwards into bytes that would otherwise be emitted as literals, bounded by the anchor (end of the previous sequence) and the start of the buffer.
- [E lz4c] `LZ4_count(pIn, pMatch, pInLimit)`: compares `reg_t` words with XOR, returns `LZ4_NbCommonBytes(diff)` (a count-trailing-zeros on little-endian) at the first difference, then finishes with 4-, 2- and 1-byte compares. The limit passed is `matchlimit = iend - LASTLITERALS` (5), so matches may run to 5 bytes before the end.
- [E lz4c] Match-length escape bytes are written four at a time: `LZ4_write32(op, 0xFFFFFFFF); while (matchCode >= 4*255) { op+=4; LZ4_write32(op, 0xFFFFFFFF); matchCode -= 4*255; } op += matchCode / 255; *op++ = (BYTE)(matchCode % 255);`.
- [E lz4c] The literal-length bound check in `limitedOutput` mode is `op + litLength + (2 + 1 + LASTLITERALS) + (litLength/255) > olimit`, one check per sequence, not per byte.

### 3.4 After a match: fill the table and test the next position immediately

[E lz4c] At `_resume` in the `byU32, byU16` branch (branch dev, `d04dab3`): it hashes `ip` and `ip-1`, inserts `ip-1` (`LZ4_putIndexOnHash(current-1, hPrev, ...)`), looks at the position that followed the previous occurrence of `ip-1` (`ctxIndex = prevIndex + 1`) and takes it if 8 bytes match (`LZ4_match8`), with the comment "it breaks chains of short matches, which the table alone can produce on periodic data"; otherwise it takes the normal candidate for `ip`. It inserts `ip`, and if the candidate's 4 bytes match it emits a zero-literal sequence at once: `token=op++; *token=0; ... goto _next_match;`. Only when that fails does it advance: `forwardH = LZ4_hashPosition(++ip, tableType);`.

[I] lz4_flex's comment "The `- 2` offset was copied from the reference implementation" (section 4.1) indicates the released lz4.c inserts `ip-2` after a match; the dev branch read here inserts `ip-1` and `ip` plus the `prev+1` chain test. I did not read a release tag to confirm the `ip-2` variant.

### 3.5 The decoder: shortcut, wildcopy, overlap patterns

- [E lz4c] Constants: `MINMATCH 4`, `WILDCOPYLENGTH 8`, `LASTLITERALS 5`, `MFLIMIT 12`, `MATCH_SAFEGUARD_DISTANCE ((2*WILDCOPYLENGTH) - MINMATCH)` = 12 "ensure it's possible to write 2 x wildcopyLength without overflowing output buffer", `FASTLOOP_SAFE_DISTANCE 64`.
- [E lz4c] `LZ4_wildCopy8(dstPtr, srcPtr, dstEnd)`: `do { LZ4_memcpy(d,s,8); d+=8; s+=8; } while (d<e);`, "can overwrite up to 8 bytes beyond dstEnd".
- [E lz4c] `LZ4_FAST_DEC_LOOP` defaults to 1 only on x86, x86-64, aarch64, PPC64 and fast-misaligned RISC-V 64, else 0. Wasm is not in the list, so a wasm build of lz4.c runs only the safe loop unless `LZ4_FAST_DEC_LOOP` is defined on the command line. The comment above `LZ4_WILDCOPY64` states: "On wasm, it depends on the host cpu (faster on Apple silicon, slower on x86-64) : it's not enabled by default, but can be, with LZ4_FAST_DEC_LOOP, from the build command".
- [E lz4c] Safe loop, the "two-stage shortcut for the most common case": with `shortiend = iend - 14 - 2` and `shortoend = oend - 14 - 18`, if `ll != RUN_MASK && (ip < shortiend) & (op <= shortoend)`: `LZ4_memcpy(op, ip, 16); op += ll; ip += ll;` then read offset, and if `ml != ML_MASK && offset >= 8 && match >= lowPrefix`: `LZ4_memcpy(op+0, match+0, 8); LZ4_memcpy(op+8, match+8, 8); LZ4_memcpy(op+16, match+16, 2); op += ml + MINMATCH; continue;`. No per-byte checks, no variable-length copies, in the common case.
- [E lz4c] Safe loop general path: literals via `LZ4_wildCopy8(op, ip, cpy)` unless `(cpy > oend-MFLIMIT) || (ip+ll > iend-(2+1+LASTLITERALS))`, in which case they "must be the last literals of the block", are copied exactly (`LZ4_memmove`) and the loop ends; the format rule 3 is what makes "within 12 of the end" mean "last sequence". `read_variable_length(&ip, iend - RUN_MASK)` for literals and `read_variable_length(&ip, iend - (1 + LASTLITERALS))` for matches, each returning `rvl_error` on hitting the limit; the match-length limit encodes "after match length extension bytes, at least 1 token + LASTLITERALS literals must remain".
- [E lz4c] Match copy in the safe loop: offset validated once (`if ((checkOffset) && (unlikely(match + dictSize < lowPrefix))) goto _offset_error;`), end rule enforced (`if (unlikely(op+ml > oend-LASTLITERALS)) ... goto _dst_too_small;`), then `if (unlikely(op+ml > oend-MATCH_SAFEGUARD_DISTANCE)) { op = LZ4_copyMatchExact(op, match, ml); ... continue; }` else `LZ4_memcpy_using_offset_base(op, match, cpy, offset)`.
- [E lz4c] `LZ4_memcpy_using_offset_base(dstPtr, srcPtr, dstEnd, offset)`, "copy a match of length >= MINMATCH (srcPtr + offset == dstPtr, overlap allowed), can overwrite up to 12 bytes beyond dstEnd": with `static const unsigned inc32table[8] = {0, 1, 2, 1, 0, 4, 4, 4}; static const int dec64table[8] = {0, 0, 0, -1, -4, 1, 2, 3};`, `if (unlikely(offset < 8)) { LZ4_write32(dstPtr, 0); dstPtr[0] = srcPtr[0]; dstPtr[1] = srcPtr[1]; dstPtr[2] = srcPtr[2]; dstPtr[3] = srcPtr[3]; srcPtr += inc32table[offset]; LZ4_memcpy(dstPtr+4, srcPtr, 4); srcPtr -= dec64table[offset]; } else { LZ4_memcpy(dstPtr, srcPtr, 8); srcPtr += 8; } dstPtr += 8; /* srcPtr is now at least 8 bytes behind dstPtr */ LZ4_memcpy(dstPtr, srcPtr, 8); if (dstEnd > dstPtr + 8) { LZ4_wildCopy8(dstPtr + 8, srcPtr + 8, dstEnd); }`. The `LZ4_write32(dstPtr, 0)` is the offset-0 clearing the spec mentions ("silence an msan warning when offset==0").
- [E lz4c] Fast loop (not default on wasm): literals by `LZ4_wildCopy32` (two 16-byte copies per step, "because it must be compatible with offsets >= 16") or `LZ4_wildCopy64`; short literals by a fixed `LZ4_memcpy(op, ip, 16)`; matches `offset < 16` by `LZ4_memcpy_using_offset`, which builds an 8-byte pattern `v` for offsets 1 (`MEM_INIT(v, *srcPtr, 8)`), 2 and 4 and then stores `v` repeatedly, and falls back to `LZ4_memcpy_using_offset_base` for other offsets; matches `offset >= 16` by `LZ4_wildCopy32`. It bails to the safe loop when `op + ml >= oend - FASTLOOP_SAFE_DISTANCE` or `ip > iend-(16 + 1)`.

## 4. lz4_flex 0.11.6, Zig 0.16, and existing Zig ports

### 4.1 lz4_flex compressor: what differs from the reference and from the Zig port

All [E flex] from `src/block/compress.rs` and `src/block/hashtable.rs` unless marked.

- Table selection (`compress_into_sink_with_dict`): `if dict_data.len() + input.len() < u16::MAX as usize { HashTable4KU16::new() } else { HashTable4K::new() }`. `HASHTABLE_SIZE_4K = 4 * 1024`, `HASHTABLE_BIT_SHIFT_4K = 4`. `HashTable4KU16::get_hash_at` is `hash(get_batch(input, pos))` with `fn hash(sequence: u32) -> u32 { (sequence.wrapping_mul(2654435761_u32)) >> 16 }`, and `get_at`/`put_at` index `self.dict[hash >> 4]`. Net: a 12-bit index, 4096 `u16` entries, the same hash and the same number of slots as the Zig port's `hash4` (`>> 20`). The `hash5` variant exists only for `target_pointer_width = "64"` and for the `HashTable4K`/`HashTable8K` types; `HashTable4KU16` overrides `get_hash_at` to the 4-byte hash on every target. The table is allocated zeroed (`alloc::vec![0; HASHTABLE_SIZE_4K]`, comment: "optimized call alloc_zeroed, vs. alloc + memset").
- Start: `if cur == 0 && input_stream_offset == 0 { let hash = T::get_hash_at(input, 0); dict.put_at(hash, 0); cur = 1; }` with the comment "According to the spec we can't start with a match", so slot value 0 means "position 0" as in lz4.c.
- Skip strength: `const INCREASE_STEPSIZE_BITSHIFT: usize = 5;` with `non_match_count = 1 << INCREASE_STEPSIZE_BITSHIFT` and `step_size = non_match_count >> INCREASE_STEPSIZE_BITSHIFT; non_match_count += 1;` per probe. Step 1 for 32 misses, then 2, and so on: twice as aggressive as the reference's `LZ4_skipTrigger = 6`.
- Candidate test, in this order: `if input_stream_offset + cur - candidate > MAX_DISTANCE { continue; }` then `if cand_bytes == curr_bytes { break; }`, with `MAX_DISTANCE = (1 << 16) - 1` (`mod.rs:63-64`). Distance first, bytes second, the reverse of lz4.c's documented preference.
- Backward extension: `backtrack_match(input, &mut cur, literal_start, candidate_source, &mut candidate)` runs right after the search loop: `while *candidate > 0 && *cur > literal_start && input[*cur - 1] == source[*candidate - 1] { *cur -= 1; *candidate -= 1; }` (safe-encode variant). The Zig port has no equivalent.
- Match counting: `count_same_bytes` compares `usize` chunks with XOR and `trailing_zeros() / 8`, over `&input[*cur..input.len() - END_OFFSET]` where `const END_OFFSET: usize = LAST_LITERALS + 1;` = 6 with the comment "we must end the matches 6 bytes before the end, 1 more than required by the spec" (`mod.rs:52-55`). [I] The Zig port's `matchlimit = len - 5` can therefore produce a one-byte-longer final match than lz4_flex; this is not where the gap comes from.
- Post-match insert: `let hash = T::get_hash_at(input, cur - 2); dict.put_at(hash, cur - 2 + input_stream_offset);` with the comment "The `- 2` offset was copied from the reference implementation, it could be arbitrary." Nothing else is inserted inside the match; the next loop iteration inserts `cur` itself. The Zig port inserts neither `cur - 2` nor anything inside the match.
- Termination: `end_pos_check = input.len() - MFLIMIT` (12) and `if cur > end_pos_check { handle_last_literals(...) }`; inputs shorter than `LZ4_MIN_LENGTH = MFLIMIT + 1` are emitted as one literal run (`compress_internal`, `mod.rs:61`).
- Output buffer: `get_maximum_output_size(input_len) = 16 + 4 + (input_len * 110 / 100)`, checked once at entry (`if output.capacity() - output.pos() < get_maximum_output_size(...) { return Err(OutputTooSmall) }`); `compress` allocates `vec![0u8; max_compressed_size]` (safe-encode) and writes through `SliceSink`. [I] The Zig port's `append` per byte re-checks capacity each time; a preallocated slice of this bound removes those checks.
- Literal copy: `copy_literals_wild`; the unsafe variant's comment is the one relevant data point on small copies: "This used to be a wild copy loop of 8 bytes, but the compiler consistently transformed it into a call to memcopy, which hurts performance significantly for small copies, which are common." It copies fixed 8, 16 or 24 bytes for lengths up to 24.

Summary of compressor differences versus the Zig port: same hash, same slot count, same window; lz4_flex adds backward extension, the `cur - 2` insert, skip acceleration, word-at-a-time match counting and a preallocated output. [I] Of these, only backward extension and the `cur - 2` insert can make output smaller; acceleration and the `END_OFFSET = 6` limit can only make it larger. The 1.4% gap is therefore attributable to the first two.

### 4.2 lz4_flex safe decoder (`decompress_safe.rs`, `sink.rs`)

- [E flex] Hot-loop guard in `decompress_internal`: `safe_input_pos = input.len().saturating_sub(16 + 2)`, `safe_output_pos = output.capacity().saturating_sub(16 + 18)`, and `if does_token_fit(token) && input_pos <= safe_input_pos && output.pos() < safe_output_pos { ... }` where `does_token_fit` is true when neither nibble is 15.
- [E flex] Inside: `let input: &[u8; 16] = input[input_pos..input_pos + 16].try_into().unwrap(); output.extend_from_slice_wild(input, literal_length);` (one bounds check for 16 bytes), then `read_match_offset` (rejects 0 with `OffsetZero`), `match_length = MINMATCH + (token & 0xF)`, `let (start, did_overflow) = output.pos().overflowing_sub(offset); if did_overflow { return Err(OffsetOutOfBounds) }`, then `if offset >= match_length { output.extend_from_within(start, 18, match_length) } else { output.extend_from_within_overlapping(start, match_length) }`. The comment: "In this branch we know that match_length is at most 18 (14 + MINMATCH). But the blocks can overlap, so make sure they are at least 18 bytes apart to enable an optimized copy of 18 bytes."
- [E flex] `SliceSink::extend_from_within(start, wild_len, copy_len)` is `self.output.copy_within(start..start + wild_len, self.pos); self.pos += copy_len;` (a fixed-size `memmove` of 18, 32 or 64 bytes). `extend_from_within_overlapping(start, num_bytes)` is `for i in start + offset..start + offset + num_bytes { self.output[i] = self.output[i - offset]; }`, a byte loop with bounds checks. `extend_with_fill` is `self.output[self.pos..self.pos + len].fill(byte)`.
- [E flex] Slow path: `read_integer` per escaped length, `LiteralOutOfBounds` and `OutputTooSmall` checks, `extend_from_slice` for literals, then `duplicate_slice`: non-overlapping matches use `extend_from_within(start, 32, ml)` when `ml <= 32` and 32 bytes of capacity remain, `extend_from_within(start, 64, ml)` for `33..=64`, else an exact copy; overlapping matches go to `duplicate_overlapping_slice`: `if offset == 1 { let val = sink.byte_at(start); sink.extend_with_fill(val, match_length); } else { sink.extend_from_within_overlapping(start, match_length) }`.
- [E flex] `decompress(input, min_uncompressed_size)` allocates `vec![0; min_uncompressed_size]` (zero-filled) and truncates afterwards.

[I] So lz4_flex's safe decoder, the one the Zig port ties with, has no `inc32table`-style overlap copy: it wins on the common case (fixed 16 and 18-byte copies, hoisted checks) and is as slow as the Zig port on overlapping matches with offset 2..17. Adopting both lz4.c's `LZ4_memcpy_using_offset_base` and the hoisted shortcut should put the Zig decoder ahead of it, not merely level.

## 5. Recommendations, in order

Each item says what is measured in a source and what is inferred.

### 5.1 Ratio (close the 1.4%)

1. **Backward extension (catch up).** Measured in source: lz4.c and lz4_flex both do it (`LZ4_compress_generic_validated` "Catch up"; `backtrack_match`). [I] Highest expected effect: every match whose true start is inside the pending literals currently loses the leading bytes to the literal run, which costs both the literal bytes and, often, the escape byte. Implementation in `lz4Compress`: after accepting `cand`, `while (i > anchor and cand > 0 and src[i-1] == src[cand-1]) { i -= 1; cand -= 1; }` before computing `lit`. Cost: a few compares per match.
2. **Insert positions after the match.** Measured in source: lz4_flex inserts `cur - 2` after each match; lz4.c dev inserts `ip-1` and `ip` and tests `ip` immediately for a zero-literal sequence (section 3.4). [I] Start with the lz4_flex behaviour, since that is the comparison target; then try lz4.c's immediate re-test, which saves a loop iteration per back-to-back match.
3. **13-bit `u16` table (8192 entries, 16 KB).** Measured in source: lz4.c uses `LZ4_HASHLOG + 1` for `byU16` and asserts `idx < 65536` (section 3.1). [I] Fewer collisions on a 4 KB input than lz4_flex's 4096 slots, at the same memset cost as today. Or keep 4096 slots as `u16` to halve the memset (8 KB). Either way positions fit in `u16` because blocks are under 64 KB (`BLOCK_TARGET = 4 KB`, `engine.zig`). Use 0 as "empty" by pre-inserting position 0 and starting at `i = 1`, as both lz4.c and lz4_flex do, so the table can be zeroed rather than filled with `0xffff`.
4. **Keep `matchlimit = len - 5`.** Measured in source: lz4.c uses `iend - LASTLITERALS`; lz4_flex uses `len - 6` (section 4.1). The Zig port is already at the spec maximum here.
5. **Do not add lazy matching.** Measured in source: absent from lz4.c's fast path, lz4_flex, and all five Zig ports; the only chained search read is HC-tier (`lz4hc.zig` exists in jedisct1's port, not read). [I] It trades compressor speed for ratio, which is not the goal.
6. **Skip strength is for speed, not ratio.** Measured in source: both implementations only ever increase `step` after a run of misses (sections 3.2, 4.1). [I] Add it with `acceleration = 1`, trigger 6 as in lz4.c, to protect compressor speed on incompressible values (already-compressed blobs); it should not change output on compressible data and may cost a little on hard data, where lz4_flex (trigger 5) pays more.

### 5.2 Decode speed

1. **Hoist the checks and copy fixed sizes.** Measured in source: lz4.c's two-stage shortcut (`ip < iend - 16`, `op <= oend - 32`, token nibbles not 15, `offset >= 8`: copy 16 literal bytes and 8+8+2 match bytes) and lz4_flex's hot loop (`input_pos <= len - 18`, `output.pos() < cap - 34`, `does_token_fit`, then 16 literal bytes and 18 match bytes) (sections 3.5, 4.2). (run) In Zig a comptime-length `@memcpy` of 16 bytes is two `i64` load/store pairs (or one `v128` pair), while the current runtime-length copy is a `memory.copy` per sequence. [I] This is the single largest decode change. It needs the output buffer to have at least 34 bytes of slack past `size`, which the allocator gives for free (section 4.3), or the checks must fall back to the exact path near the end as lz4.c does.
2. **Overlap copy by pattern.** Measured in source: `LZ4_memcpy_using_offset_base` with `inc32table`/`dec64table` turns any `offset < 8` into one 4-byte copy, one adjusted 4-byte copy and then 8-byte wildcopies; `offset >= 8` is plain 8-byte wildcopy (section 3.5). lz4_flex's safe decoder only special-cases `offset == 1` and otherwise loops byte by byte (section 4.2). [I] Implement the lz4.c version with `@memcpy` of comptime 4 and 8 bytes and a `@splat` fill for `offset == 1`; this is where the Zig decoder can pass lz4_flex rather than tie it. It requires 12 bytes of slack ("can overwrite up to 12 bytes beyond dstEnd"), else the exact byte loop within `MATCH_SAFEGUARD_DISTANCE` of the end.
3. **End-of-block handling by the spec's rules.** Measured in source: the spec permits rejecting blocks whose last match starts within 12 bytes of the end or whose last 5 bytes are not literals (section 2); lz4.c uses this to treat "literals reach `oend - 12` or `iend - 8`" as "this is the last sequence" and to make `op + ml > oend - 5` an error (section 3.5). [I] Adopting the same rules lets the Zig decoder drop the per-sequence `i == src.len` test and validate the tail once.
4. **Reuse the output buffer.** Measured in source: `BrkAllocator.alloc` is a free-list pop after the first block (section 4.3), so this is a small win; `decodeSst` already frees per block. [I] A caller-owned scratch buffer avoids the alloc/free pair and the `errdefer` path entirely; worth doing only after 1 and 2.
5. **`simd128` last, and measured.** Measured in source: lz4.c's authors say wide copies on wasm are "faster on Apple silicon, slower on x86-64" and leave them off by default (section 3.5); Zig emits `v128` only with `-mcpu=generic+simd128` (run). [I] Try a 16-byte `@Vector(16, u8)` literal copy only after the scalar shortcut is in, and keep a non-SIMD build unless the engine's target browsers are all known to support SIMD; browser support was not researched here.

### 5.3 Compressor speed (secondary)

- **Preallocate the output.** Measured in source: lz4_flex checks `16 + 4 + len * 110 / 100` once and writes through a slice (section 4.1); lz4.c checks per sequence, never per byte (section 3.3). [I] Replace `Bytes.append` per byte with `ensureUnusedCapacity(bound)` followed by `appendAssumeCapacity` or direct index writes.
- **Count matches a word at a time.** Measured in source: `LZ4_count` and `count_same_bytes` XOR 8 bytes and count trailing zeros (sections 3.3, 4.1); (run) `@ctz(u64)` is one `i64.ctz`. [I] Replace the byte loop in `lz4Compress` with `readInt(u64)` XOR and `@ctz(x) / 8`, with the 4/2/1 tail, bounded by `matchlimit`.
- **Hash one position ahead.** Measured in source: lz4.c computes `forwardH` for `forwardIp` before inserting the current position (section 3.2). [I] Minor on wasm; try after the two above.
