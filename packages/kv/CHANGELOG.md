# @opfs-lsm/kv

## 0.5.0

### Minor Changes

- 63a1f5a: `openDb` now opens in Safari and iOS 16 to 25, which have no `createWritable()`, in Samsung Internet and Android WebView, which have no SharedWorker, and inside a dedicated WebWorker in every browser, where it used to reject. Where the page has no SharedWorker, each handle starts the host in a dedicated Worker. A host writes SST files only in a SharedWorker whose OPFS files have `createWritable()`. Any other host still repairs and empties the database, but nothing flushes or compacts: every write stays in the IndexedDB WAL and in each tab's memory, each open replays the whole WAL, a delete frees no space until `dangerousDestroy`, `destroyDb` or an open whose host writes, and `onStorageFull` is never called. `openDb` still rejects with `StorageUnavailableError` where OPFS or a worker is missing, as in Node.
- 71f146f: A run's block index is stored once, in the manifest. Each run file also held a copy of it that only compaction read. A run file is now its data blocks, its Bloom filter and a 24-byte footer, and a compaction step takes the block layout of its inputs from the manifest. A run of 2,000 entries with 27-byte keys and 100-byte values is 0.18% smaller, the read that loads a run's Bloom filter no longer carries the index, and `openDb` loads 0.7 kB less in all before compression, 0.1 kB less with brotli.
  
  The SST format is now version 3. A database written by an earlier version still opens and reads, without its Bloom filters, and every compaction throws `CorruptDatabaseError`, so writes stop once L0 fills. Call `destroyDb` and open it again.
- 082a174: The body of `update` can read more keys: `tx.read(keys)` returns their values in the same state as the update's own. Use it for a key the body learns only from what it read, such as the target of a pointer. A value held in memory comes back at once, so the update still costs what a `put` costs. For any other, `read` ends that run of the body, kv loads the value and runs the body again. The `tx` of `update` has the new type `UpdateTx`. The main-thread JavaScript grows by 0.1 kB gzip, to 19.5 kB.
- f5a1d19: The SharedWorker host now flushes and compacts in a browser with no `createWritable()`, as Safari and iOS 16 to 25, when it can write files another way. It stages each file as `<name>.crswap` through a sync access handle, flushes it, and renames it into place. The OPFS spec gives that handle to dedicated Workers only, so the worker first writes one scratch file in `opfs-lsm/` and stages its files only when the byte reads back. Where the scratch file fails, the host writes no file, as before. This ran in Safari 18.6 on macOS, from its SharedWorker, and in desktop Chrome inside a dedicated Worker. Safari 16 and 17 and iOS are untested. The host of a dedicated Worker, where the page has no SharedWorker, still writes no file. A page that imports `destroyDb` no longer bundles the file writer.

### Patch Changes

- c443397: A scan reads the memtable's rows in place instead of copying every row in its bounds first, so `range({ limit })` and a paged scan over a full memtable cost what they read. A range delete rewrites only the memtable chunks it touches instead of the whole table.
- 147387f: `openDb` no longer waits for IndexedDB before it reads the manifest and opens the runs. While the WAL database opens, it reads the newest manifest in the folder and opens its runs, so a cold tab whose IndexedDB opens slowly resolves `openDb` sooner: a fresh-tab open of 100,000 entries went from 10.3 to 8.97 ms on an Apple M2 Pro. The main-thread bundle grows by about 150 gzip bytes, to 19.4 kB.
- 901139c: An `update` now reads every write its handle issued before it. An update called right after a `put` of the same handle could run before that put when the put waited for the next group commit, or when the browser refused the put's group for lack of space: its `body` read the older value, and the put then replaced what the update wrote.
  
  A `changes()` listener that calls `close()` no longer takes the event being delivered away from the listeners after it. Every listener gets the append, then `closed`.
- 219bc51: A `get` or `getMany` of a view keeps its run files until it settles, as the view's scans do. A write that commits while its handle closes reaches the other tabs.
- 79b6b33: The SharedWorker an app loads no longer counts IO, flushes, compactions or wasm memory, and the tab no longer counts its WAL appends. Only `@opfs-lsm/kv/testing` keeps those counters for `readStats`: a database it opens in a browser uses a second SharedWorker entry with a meter. `readStats` now rejects with `StorageUnavailableError` for a database opened with plain `openDb`: open it with `openDbWith` or `openHarnessDb` of `@opfs-lsm/kv/testing`. An app downloads about 0.5 kB less brotli after `openDb` and 0.1 kB less gzip at import.

## 0.4.0

### Minor Changes

- 17f9b12: Every run is stored raw, at every level. Runs from L2 down held LZ4 blocks, and each read of one unpacked a whole 4 KiB block, so reads slowed down once a database passed about 40 MB and its data reached L2. At 1,000,000 entries a random `get` ran at 219k ops/s on LZ4 runs and at 352k on the same data raw, and `getMany` and `count` were 1.85 and 1.88 times slower. Raw runs give up the 26% of disk space that LZ4 saved at that size. The wasm engine is 3.2 kB smaller gzip, and `openDb` loads about 3 kB less brotli in all.
  
  The SST format is now version 2, with a 40-byte footer and no codec field. A database written by an earlier version still opens, then the first read or compaction that reaches one of its runs throws `CorruptDatabaseError`. Call `destroyDb` and open it again.

### Patch Changes

- 4437556: A write that waits behind another append when `destroyDb`, or the browser, closes the handle's IndexedDB connection now rejects with `ClosedError`. It rejected with IndexedDB's `InvalidStateError`.
- 327c0e8: The wasm engine (`wasm/engine.wasm`) is built from AssemblyScript instead of Rust. It takes the same calls and writes the same bytes, so stored data reads as before. The module is about half the size, 6.5 kB gzipped instead of 13.3 kB, and a flush or a compaction step reaches less wasm memory. Building it from source needs only `pnpm install`.
- 66344c2: `getMany` reads many large values faster. A retry after a page load looks up only the keys that missed, the block index search skips the bytes a key is known to share with its bounds, and pages that fill a file read share its buffer instead of each taking a copy.
- 488ee4d: A `sync()` made while another one ran, and a `put` whose row committed while it waited on one, no longer reject with IndexedDB's `InvalidStateError` when `close()` comes in between. They settle as a lone `sync()` cut off by `close()` does, and the `put` resolves with its seq: its write is stored.
- eeaff75: A `dangerousDestroy` in flight when its handle closes now rejects with `ClosedError`. It rejected with a plain `Error`, or never settled when the handle closed between two of its steps.
- 7d39e3f: A cold `get` starts the layout reads of every level it passes at once, instead of waiting for one level before it asks the next. It still stops at the first level that may hold the key, so it reads no page of an older version. Over 120 cold tabs on a settled 100,000-key store, the first `get` after opening has a p90 of 2.9 ms instead of 3.5 ms.
- eeaff75: `dangerousDestroy` no longer rejects with `CorruptDatabaseError` while another handle keeps writing. Each write that landed between its read of the log and its commit made the commit stale, and a steady writer used up every try. The commit now reads the head itself.
- 634bf1a: Smaller bundles: kv's main-thread JavaScript is 19.5 kB gzip, from 19.8 kB, and its SharedWorker chunk 13.4 kB, from 13.6 kB. The docstore chunk is 0.7 kB smaller before compression. Some docstore error messages changed with it: a `limit` or `offset` that is not valid says "must be an integer of at least 1" (or 0), a schema with a bad `include`, `drop` or text index reports one message for each, and a stored value that is not a JSON object reports "a stored value is not a JSON object". The error classes and codes are the same. A `by` list with a hole, such as `["a", ,]`, is now refused with code `schema`, as a hole in `include` or `drop` is.
- df04143: An `openDb` that fails no longer removes another tab from the SharedWorker's count of open handles. Before, with one other tab open, the SharedWorker stopped flushing that tab's database at `maxWalBytes` and stopped its storage-full offers. The same holds for a handle the browser closes while it opens, which used to leave its `maxWalBytes` with the SharedWorker for good.
- 2def7c4: A database written without a 2 s pause is flushed once an eighth of `maxWalBytes` has waited 5 s, so a tab opened after a long typing session no longer replays up to `maxWalBytes` of small records.
- 402b24d: The SharedWorker keeps the count of the rows written while one of its flushes waited and then found nothing left to fold. It dropped that count, so the WAL could grow past `maxWalBytes` with no flush until another `maxWalBytes` arrived or the database went quiet. This needs a second host on the database, as when tabs run without a SharedWorker.
- fb5b609: A write places its rows in the memtable with fewer byte compares. The search skips the bytes that both of its bounds already share with the key, so keys with a long common prefix, as docstore's are, cost one pass over that prefix and not one per step. An import batch of 1,000 rows is 3 to 5% faster in the tracker benchmark.
- eb929d8: A compaction step that a flush waits for on a full L0, or soon will, overlaps its file waits with its work: one output write stays in flight, and its last source, the level it merges into, is read one window ahead. A long bulk write that outruns compaction ends sooner, and its writes wait less. Any other step runs as before.
- 047eed4: `openDb` opens the runs of the recorded generation as soon as it has read which one that is, while the WAL tail's records are still being read, instead of after them. The tail is read in ranges of 100 records, all in flight at once, so one range decodes while the next is read. A tab that opens a database with unflushed writes is ready sooner.
- ec242eb: A key of 65 bytes to 1 KiB is now copied into a shared 8 KiB buffer, as values of that size are, instead of an array with its own buffer, which Chrome and Node allocate several times slower than the copy. This holds for the key a write keeps, the key of an entry that `range`, `rangeValues` and `rangeJoin` hand out, and the key `encodeTuple` returns. Each is still a copy you may change. Read it through `byteOffset` and `byteLength`, and `slice()` it before you post, store or transfer it. A point read hashes its key for the Bloom filters once, not once per level.
- 3f59e5f: A value of 65 bytes to 1 KiB that a read hands out is now a view of a shared 8 KiB buffer, as Node's Buffer pool makes them, instead of an array with its own buffer. It is still a copy you may change. Read it through `byteOffset`, a multiple of 8, and `byteLength`. Posting or storing it clones the whole shared buffer, and transferring that buffer detaches the other copies, so `slice()` it before you post, store, transfer or keep it.
- 72d4295: A write copies each value of 65 to 1,024 bytes into a shared pool buffer, as a read already does, instead of allocating a buffer per value. `tx.put` still copies at the call. A short copy no longer uses `slice`, which is a view on a Node `Buffer`.
- ac545e6: A key or value that is not a `Uint8Array` now throws `ConstraintError`. Before, a value such as an `ArrayBuffer` overwrote other stored values.
- 44b72e1: Importing `@opfs-lsm/kv` adds 19.2 kB of JavaScript to the main bundle (gzip), down from 20.0 kB. A tab no longer carries the writes of recovery. When an open finds that IndexedDB and OPFS disagree, after a power loss or a `destroyDb`, it asks the SharedWorker to record the repair, so only one repair runs however many tabs open at once. An open of a healthy database or of a new one is unchanged, and does not wait for the SharedWorker.
- fa776c8: The reserve file comes back after an `onStorageFull` handler frees space outside kv while a few unflushed writes wait in the WAL, and after a handler that frees space with `dangerousDestroy`. Before, the host kept no reserve until enough later writes started a flush. A `range` scan no longer hands out an empty key, out of order, after the app transfers the `ArrayBuffer` of a value it read earlier in the scan.
- 33d7488: Fix four faults. A sweep keeps the runs of a manifest whose IndexedDB commit failed, so two power losses can no longer make the database read rows that are not a log prefix. Writes of no bytes, such as a range delete of everything, count toward `maxWalBytes`, so the host flushes them. A handle writes again after a refused write whose call to the host failed. Two `changes()` or `onStorageFull()` subscriptions of one function end apart.
- 3aa934e: `openDb` rejects with `StorageUnavailableError`, with the browser's error as `cause`, when a browser API it needs is there and refuses with a `DOMException`: OPFS, `new SharedWorker()` or `indexedDB.open()`, as in a Firefox private window or on a page of an opaque origin. A handle whose IndexedDB connection the browser closes by force, as clearing site data does, reports `closed` with reason `"destroyed"`, and calls made after it reject with `ClosedError`. An IndexedDB transaction the browser aborts no longer leaves an unhandled rejection behind the call's own. A database name that is not a string throws `ConstraintError`. `openHarnessDb` flushes to the `fs` it was given, also after an earlier open of the same name was given another.
- df04143: An `update` whose handle closes while its refused append is retried rejects with `ClosedError` or `StorageFullError`. Before, it could reject with the browser's `InvalidStateError`.
- a282ddf: `update` commits like a `put` when no other write lands between its read and its commit: one IndexedDB round trip, where it took a transaction of its own. Concurrent updates still lose nothing. When another write does get in first, `body` runs a second time inside a transaction, so keep it free of side effects. A body that writes nothing runs twice too. After such a loss the handle's updates use the transaction alone until one finds no other write, so two tabs that write at once pay what they paid before. The updates of one handle run one at a time, in call order, and a `changes` subscriber can receive an append with no ops, for the row of an update that ran again. The WAL row format gains a header, so a build from before this change cannot read a database that this one has written an `update` to.
- 423bec9: An `update` whose body throws now throws only what the body throws at the committed head. The body ran on what its tab had read, which can lag another tab's write, and its error reached the caller as it was. A docstore `put` could then throw `"unique"` for a value another tab had freed a moment before.
- 5dee709: A flush sorts its WAL chunk and keeps each key's last write inside the wasm engine. The worker no longer builds a map and sorts in JavaScript first. Folding and encoding a default chunk of distinct keys takes about half the time, and the engine's peak memory during a flush is about 20% lower. A chunk that rewrites the same keys many times folds slower than before.
- 93c2a32: Writes that wait at the `memtableBytes` limit append in call order: a `put` called while an earlier one waits no longer lands first, so the later value is the one stored.

## 0.3.0

### Minor Changes

- 65a7368: `destroyDb(name)` now removes the database: its OPFS folder and its IndexedDB database go, and every open handle on it, in every tab, closes first with a `closed` event whose new `reason` field is `"destroyed"`. On a name with nothing stored it creates nothing. `dangerousDestroy()` still empties the database and keeps it open.
- 206b371: The manifest format is now version 5, without the unused `tombstoneSeq`. A database written by an earlier version refuses to open with `CorruptDatabaseError`; call `destroyDb` and open it again.
- 02a506c: `openDb` takes `reserveBytes`, 24 MiB unless given. The SharedWorker keeps a file of that size and deletes it when the browser refuses a write, so the write lands, then calls `db.onStorageFull` in one tab to free space. `put`, `delete`, `batch` and `update` reject with `StorageFullError` when the browser refuses them again. `maxBytes`, `db.onPressure`, `Pressure` and `PressureHandler` are removed: pass no option for the default reserve, and move the handler to `db.onStorageFull`.
- aaa559c: A scan leaves each record of a run in its block until it yields the entry, and the merge compares keys there. An entry that `count` counts, that a newer version or a tombstone drops, or that `offset` passes over no longer copies its value, and copies its key only when it waits in the merge through several compares. The merge keeps its waiting sources in a short sorted list instead of a binary heap, and remembers which sources tie on a key, so two versions of one key are compared once.
  
  A scan under a range delete compares its entries with the delete's bounds in place too, and only with the range deletes that reach into the scan's own bounds.
  
  `Range.offset` is new: `range`, `count` and `rangeJoin` pass over that many entries before the first one, and `limit` counts from there. A `limit` or an `offset` that is not an integer of 0 or more now rejects with `ConstraintError`.
  
  `getMany(keys)` is new on `Db` and on a `view` snapshot. It reads every key in one read, in the order asked, and the pages they lack load together. With a second argument, `getMany(keys, decode)`, a value is not copied: `decode` gets the bytes where they are stored and returns what to keep. `rangeJoin` takes the same `decode` for the values it joins, and `rangeValues(range, decode)` on a `view` snapshot returns a range's entries with each value decoded that way.
- 34430fb: `@opfs-lsm/kv/tuple` is a new subpath export. It encodes a tuple of null, booleans, finite numbers and strings as key bytes that sort in tuple order, decodes them, and returns the `KeyBounds` of every key that continues a tuple. To scan the keys under a tuple prefix, use `tupleBounds`, not `prefixBound`. `prefixBound` also returns the keys where the last string of the prefix goes on with U+0000, so `["a"]` would match `["a\u0000b"]`. The main `@opfs-lsm/kv` entry is unchanged. `@opfs-lsm/docstore` now imports this codec instead of carrying a copy, and writes the same key bytes.
- 58de646: `rangeJoin` moved from `Db` to the `view` snapshot: `db.rangeJoin(range, keyOf)` is now `db.view((snap) => snap.rangeJoin(range, keyOf))`, with the same `{ entry, joined }` hits. A view can now join, so the scan and the joined reads share the view's pin with its other reads.

### Patch Changes

- 44be297: A Bloom filter check on a `get` computes each probe's bit with integer arithmetic. The remainder that picks the bit ran on doubles, which took most of the check's time.
- 830fa2a: Smaller bundles: `openDb` ships about 760 bytes less brotli and `openDocStore` about 800 less, with no change to the app API, to the disk format or to any read or write path. Two changes to the `@opfs-lsm/kv/testing` entry come with it: `EngineHost.compact(name)` is gone, since the SharedWorker no longer ships a method that only tests call, and the `trace` option of `openHarnessDb` is gone with the `OpenTrace` and `OpenSpan` types and the open timing they recorded.
- 92dd1a4: A flush folds its WAL records with less work in the SharedWorker. To keep the last write of each key it named every key by a hex string, built one byte at a time, and it now uses a string of one char per byte. The runs it writes are the same.
- 4ffe314: A `get` of a flushed key copies its value once. It copied the key out of the SST block, copied the value twice and read the seq through a BigInt, and a caller only ever saw one value copy. `ViewSnapshot.get`, `update` and `rangeJoin` read through the same path.
- a61d279: The host flushes a database that got no write for 2 seconds, when at least an eighth of `maxWalBytes` is waiting. A tab that opens it then replays a short WAL tail instead of everything written since the last flush.
- 5163013: The merge under `range` and `count` allocates nothing per entry, and a source that yields several keys in a row costs one key comparison each instead of a trip through the heap.
- 578fbd7: An `openDb` that fails now closes the IndexedDB connection, the SharedWorker port and the BroadcastChannel it opened, so `destroyDb` can run next.
- bfcee61: `openDb` is faster in a fresh tab: about 3.9 ms where it took 5.0 ms on a 100,000-entry database. A flush or a compaction now stores the bytes of the manifest it records in IndexedDB, so a tab opens the run files while it reads the manifest file, instead of after. The open also looks up `opfs-lsm/` while it waits for its lock, and checks recovery while it reads the WAL tail and opens the runs. A database written by an earlier version opens as before and gets the copy at its next flush.
- e42c671: A `range` iterator answers a `next()` whose entry is in memory in the call itself. `Db.range` and `ViewSnapshot.range` were async generators that wrapped a second one, so every entry spent several promise turns twice, and `rangeJoin` read its scan through one as well. An iterator still answers calls in the order they were made, checks the handle on every entry, and lets go of its run files when it ends, when the caller returns early and when a read fails. It inherits from the async iterator prototype as a generator does, so `await using` and `yield*` work on it, and a `throw()` ends it as a failed read does. `return()` ignores its argument.
- 802afdd: Range scans and seeks over flushed data no longer copy every entry they step over. A scan copied each key and value as it read it out of an SST block, then copied the entries it returned a second time. It now reads entries in place in the block and copies only the ones it returns. In the `kv/fillseq` benchmark, 100 seeks went from 749 ms to 517 ms, 10 seeks from 102 ms to 79 ms, and a full ordered scan from 90 ms to 72 ms (median of 6 runs each).
- c87f21f: A scan copies each entry it yields once. It made a view of the key and of the value in the SST block and then copied both, four arrays for the two a caller keeps. It now copies the key out of the block as it reads it, hands that copy to the caller, and copies the value only for an entry it yields. `count` and the entries a merge skips copy no value.
- cb12766: The JavaScript a page downloads to import kv is 19.9 kB gzip, down from 20.4 kB. The tab no longer ships its own LZ4 decoder: the wasm engine, which an open already waits for, decodes every block. After a wasm trap the read runs once more on a fresh instance instead of falling back to JavaScript, and a block that fails there too throws `CorruptDatabaseError`. The names of the engine's statuses are in the SharedWorker bundle alone, so an error from a tab's block read gives the status number without its name.
- eb1497d: `encodeTuple` and `stringPrefixBounds` write a string of up to 64 ASCII characters without a call to `TextEncoder`. The encoded bytes are the same for every string.
- 41a7777: Opening a database, and every WAL tail read, no longer slows down right after a flush. The WAL head was found with a reverse IndexedDB cursor, and in Chrome a reverse cursor steps over every row deleted since IndexedDB last compacted: right after a flush deleted 24,700 folded records, finding the head took about 35 ms per lookup, and an open does two. kv now looks forward from `ingestedThrough` first and walks back only when a record is past it. In the `yjs/trace` benchmark, a fresh tab's open after a settle went from 64–68 ms to 16–18 ms.
- 51a92e6: Opening a database after a flush, and every `update` from a tab that is caught up, no longer reads past the rows the flush deleted. In Chrome, an IndexedDB range read past the last WAL record steps over every row deleted since IndexedDB last compacted, and kv found the WAL head with such a read: twice per open and once per `update`. kv now reads the one key after the seq the head has reached, and looks for the last key only when that key is there. In the `yjs/trace` benchmark, a fresh tab's open after a settle went from 10.1 ms to 4.7 ms, and in `kv/ycsb-a` a read-modify-write went from 1.11 ms to 0.17 ms on average (median of 5 runs each).

## 0.2.0

### Minor Changes

- 912ab8a: Bound the memory of a flush and of the memtable. `openDb({ memtableBytes })` (default 16 MiB) caps the rows a tab holds that are not yet flushed: at 7/8 of it the tab asks for a flush, and at the limit a write waits for that flush. The SharedWorker now flushes a WAL backlog in L0 runs of at most 1.75 MiB, and at 48 L0 runs a flush waits for compaction (`HostStats.l0Stops` counts the waits).
- 2edac58: `changes()` now reports what changed. An `append` event carries the record's seq and ops, and every seq a handle applies is announced once, in seq order, whether it came from this tab, from another tab's BroadcastChannel message, or from a `sync()` catch-up. A handle that skipped records a flush folded gets a `gap` event and should read again, and `close()` ends the feed with `closed`. `put`, `delete` and `batch` resolve with the record's seq, and an `append` event no longer has a `writerId`.
- cad8e27: Add `openDb({ compactionMemoryBytes })` (default 32 MiB, at least 8 MiB), the memory the SharedWorker may spend on flushing and compacting a database. One figure sets the flush run, the sources a compaction step reads, the L0 stop, the read window and when the wasm instance is replaced to give its memory back. When tabs pass different values, the host uses the smallest until the last of them closes the database. Each database has its own SharedWorker, so the budget is per database. Where one host serves several databases, as in Node, their merges now take turns, and a second one no longer falls back to the TypeScript merge. `HostStats.memory` reports the wasm memory, its peak, the merge reserve and the recycles, and `HostStats.l0Stops` moved into it.
- 2c55877: Add `db.dangerousDestroy()` and `destroyDb(name)`, which delete every record of a database. Writes acked before the destroy are gone, and writes after it land in the empty database. Every handle stays open and reads empty once it catches up, with a `gap` change event. `destroyDb` does not open the database, so it also empties one that `openDb` refuses as corrupt. One IndexedDB transaction, on disk before any file is removed, empties the database: once it resolves, the deleted records never come back, even after a power loss, and a crash before that leaves the database as if the destroy had not run. The host then removes every file no tab is reading, and the rest once their tabs move on.
- 39a80af: `Db` exposes `name`, the name passed to `openDb`.
- cbd6d5c: Add `tx.deleteRange(bounds, { through? })` to `batch`, which removes every row in `[start, endExclusive)` in one op, however many rows that is. It removes the rows written before its batch, or with `through` only those last written at or below that seq, and never its own batch's puts. Every read skips the removed rows, in every tab, and a `view` opened before it keeps reading them. `changes()` reports it as a `deleteRange` op with its `through` resolved. `KeyBounds` and `DeleteRangeOptions` are exported.
  
  Manifests move to version 4, which records the range deletes. This build refuses a database whose newest manifest is version 3 or older with `CorruptDatabaseError`, and an older build refuses a version 4 manifest the same way; `destroyDb(name)` empties either.
  
  A docstore change feed sends a `gap` when a kv range delete reaches a collection's rows.
- bb30bad: Two changes to the `@opfs-lsm/kv/testing` entry. Breaking: `EngineHost.ingest(name, waitForCompaction?)` and `IngestClient.ingest(name, waitForCompaction?)` no longer take a `through` seq; a flush always folds the WAL as it stands when the flush starts. New: `EngineHost.compact(name)` waits for a flush in flight and compacts without folding the WAL. A tab and a SharedWorker must now run the same build: the port's `ingest` message no longer carries `through`. The app API is unchanged.
- 911ab89: Add `openDb({ maxBytes })` and `db.onPressure(handler)`. When the SST files pass `maxBytes`, the SharedWorker offers `{ bytes, maxBytes, need }` to the one handle that holds the Web Lock `opfs-lsm-pressure/<name>`, and its handlers remove what the layer chooses with ordinary writes. kv never removes a row for the cap, and a write never waits for it. A handle opened with `maxBytes` and no handler warns once per offer when no handle answers.
- d33afb3: A batch no longer has a limit of 10,000 ops. The limit of 8 MiB per batch stays, and it now counts 256 bytes for each op on top of the key bytes and the value bytes, as the memtable does. A batch of small ops can hold about 30,000 of them. A batch of fewer than 10,000 ops that was within about 2.4 MiB of the limit is now over it. The separate limit of 16 MiB per value is gone: no write could reach it, because a `put` is a batch of one op.
- f31c858: `openDb` never falls back to memory. Breaking: where SharedWorker or OPFS is missing, as in Node or a dedicated WebWorker, `openDb` rejects with `StorageUnavailableError`. Before, a context with no `document` got an in-memory database with no error, while its WAL still went to IndexedDB. Tests ask for memory with `openHarnessDb({ forceMemory: true })` from `@opfs-lsm/kv/testing`. The `allowEphemeral` harness option is gone.
- bbf4302: Rows that `deleteRange` removed now leave the disk. Compaction drops them from the SST files it rewrites, and once the levels are in shape it rewrites every file that still holds such rows, so the range delete leaves the manifest and its space comes back.
- afbf970: Require the wasm engine. `openDb` now waits for the module and rejects with `StorageUnavailableError` when it does not load. Before, the SharedWorker fell back to a TypeScript encoder and merge that wrote raw blocks only.
- 9be5912: `readStats` from `@opfs-lsm/kv/testing` reports removed files as a count per path class: `IoCounters.removed` is now `Record<string, number>`, not `Record<string, IoCount>`. The byte total it reported before was wrong for any file written in an earlier session, and is gone.
- d5962d5: Trim the `Db` surface. Breaking:
  
  - `rangeFollow(range, follow)` is now `rangeJoin(range, keyOf)`, and each hit is `{ entry, joined }` where it was `{ entry, value }`.
  - `db.ingest()` is gone. Tests and benchmarks call `ingest(db)` from `@opfs-lsm/kv/testing`. The host still flushes by itself, so an app does not need it. No `Db` method rejects with `StorageFullError` any more.
  - `changes()` no longer emits an `ingest` event. A flush does not change what reads return.
  - In `view`, `snap.walHead` is now `snap.seq`, the same seq write acks and `append` events carry. `snap.generation` is gone.
  - `openDb({ memoryBudget })` is now `openDb({ cacheBytes })`.
- e041971: Export only the app API from `@opfs-lsm/kv`: `openDb`, `prefixBound`, the types of `Db`, and the error classes. Breaking:
  
  - `EngineHost`, `createLocalIngestClient`, `createPortIngestClient`, `attachEngineHostPort`, `MemoryFs`, `openBrowserFs`, `ensureEngine`, `engineUsingWasm` and the types `IngestClient`, `AsyncFs` and `IngestPolicy` are now exported from `@opfs-lsm/kv/testing` only.
  - `BrowserFs`, `FileWriter`, `SstEntry`, `encodeSst`, `decodeSst` and `DEFAULT_INGEST_POLICY` are no longer exported. `openDb` never accepted them.
- 1d97eaa: Give two storage failures a typed error, and stop a file leak. `ingest()` rejects with the new `StorageFullError` (code `quota`) when the browser refuses a flush or compaction write for lack of quota; it was a plain `Error`. `openDb` rejects with `StorageUnavailableError` when the browser's IndexedDB store fails to open, with the browser's error as `cause`; it was a raw `DOMException`. Manifest reclaim now removes the `.crswap` file Chrome leaves in `m/` when the browser dies during a manifest write.
- ac8f49f: Make a single `put`, `delete` or `batch` cheaper: the append transaction now writes only its WAL record. The head is the last key in the WAL, and the host measures a waiting WAL from its records when a tab opens. The stored format is unchanged. A tab still running an older build reads the stored head floor, so it does not see these appends; reloading that older build does not either. The records stay in the WAL.

### Patch Changes

- a410ea1: Make `put`, `delete` and `batch` one round trip to IndexedDB. The append no longer reads the head floor or waits for its record's key before the commit starts: recovery and destroy now move the WAL's key generator whenever they move the head past the records. In Chrome 157 an awaited single put went from a p50 of 148 µs to 114 µs. Databases written by earlier versions are not migrated: one that an earlier version destroyed, or recovered after a power loss, and that took no write since, loses the first writes it takes under this version.
- 594b30b: Reads of many keys at once are faster when the pages are not in memory yet. Page reads issued together are now served by one read per run of neighbouring pages. A docstore `getMany` of 3,000 ids on a cold cache is about 3.4 times faster in Chrome.
- b319e37: Stop storing the WAL head. `meta` in `opfs-lsm-wal/<name>` no longer has a `head` key: the head is the last key in `wal`, or `ingestedThrough` when no record is past it. Recovery and destroy, the only writers that move the head past the records, already set `ingestedThrough` to the new head and move the key generator with it. A tab still running an earlier version reads the old key as the head. After this version recovers or destroys the database, an `update` from that tab can take a seq this version counts as already flushed, and that write is lost. Reload such tabs after an upgrade.
- b5f8283: An open handle now follows a repair that falls back to an older manifest. When files of the recorded generation went missing under a running page and the repair emptied the WAL, every open handle kept its old runs, and its writes and `sync()` rejected with `CommitError("wal gap before seq …")` until the page reopened the database. A handle now loads the older manifest when the WAL has moved past its memtable.
- 1330fd2: Post the rows of a burst of writes to other tabs in one `BroadcastChannel` message. A tab still posts a write at once when it has not posted in the last 4 ms, and always from a hidden page; a write that lands sooner waits for the first one past that time, or for a timer, so other tabs see the writes of a burst a few milliseconds later than before. `db.sync()` still returns every acked write. The message is now `{ kind: "rows", rows }`. A tab on an earlier version reads the WAL when it gets one, and its own `row` messages no longer count toward the automatic flush, so reload tabs after upgrading. In Chrome 157, 10,000 awaited single puts ran at 0.69 to 0.78 of the speed of plain IndexedDB writes before, and at 0.82 to 0.94 after.
- 9d6d98b: In the `@opfs-lsm/kv/testing` entry, a `watch` that reaches the host with a zero or negative `compactionMemoryBytes` now gets the 32 MiB default, as `openDb` already gave it; the host used to clamp it to 8 MiB. The app API is unchanged.
- 1e3d0b1: A write reaches other tabs and the SharedWorker as the WAL row it appended, one buffer, instead of one cloned object per op. The SharedWorker takes the byte count it needs from the message instead of reading the ops. A batch of many small ops, such as a docstore write with several indexes, costs less on the main thread. The message has a new kind, so a tab of an older build on the same origin catches up from the WAL when it gets one.
  
  Checking a key or a value for a detached buffer no longer makes V8 allocate a buffer for every small array.
- 7de83db: `openDb` no longer counts the calls and bytes of each OPFS read the tab makes, so the tab bundle is 203 bytes brotli smaller. `readStats` from `@opfs-lsm/kv/testing` now reports `tab.fs` only for a database that `openHarnessDb` opened.
- b3ea475: The wasm engine loader no longer ships a Node file reader to the browser, which takes 176 bytes brotli off kv's bundle. Bundling kv with webpack no longer prints "Critical dependency: the request of a dependency is an expression". Node code that loads kv's engine, such as tests on `openHarnessDb`, gets the file reader by importing `@opfs-lsm/kv/testing`.
- 328ae0d: Shrink the open trace of the `@opfs-lsm/kv/testing` entry. `OpenSpan` loses `bytes`. The `host-scan`, `worker-ctor` and `wasm-error` spans are gone, and the `sst` span appears only when a sync loads a generation. `EngineHost.watch` and `createPortIngestClient` no longer take an `onScan` callback, and the `WatchScan` type is gone. The app API is unchanged.
- 9c9e818: `@opfs-lsm/kv` is smaller: 40.2 kB brotli after the first `openDb`, down from 47.3 kB, and 15.4 kB at import, down from 20.7 kB. `openDb` no longer bundles the in-process host and the memory filesystem that only `@opfs-lsm/kv/testing` uses, the main chunk and the SharedWorker chunk no longer carry each other's WAL and engine code, and the wasm engine drops a decoder that no production path called.
- bef2766: Two changes to the `@opfs-lsm/kv/testing` entry. `openHarnessDb` takes `maxWalBytes` directly, in place of `ingestPolicy: { maxWalBytes }`, and the `IngestPolicy` type is gone. `HostStats.l0Stops` moved out of `memory` and sits next to `flushes`. The app API is unchanged.
- fbe16fb: kv's SharedWorker bundle no longer includes the block decoding hooks and the JavaScript LZ4 decoder, which only the tab uses. The worker chunk is 372 bytes brotli smaller.
- f172e80: `openDb` resolves about 0.5 to 1 ms sooner in Chrome. IndexedDB and OPFS now open at the same time, recovery reads the WAL and lists manifests together, and a tab looks up each directory once.
- 5c5730d: `update` no longer hangs when the keys it reads sit in more run pages than `cacheBytes` holds. That covers docstore's `putMany` and `modifyMany` and the TanStack DB adapter's writes. A read now keeps the pages it loaded until it ends, outside the cache budget, so the cache never has to hold more than `cacheBytes`.
- 04db272: The SharedWorker now removes every run file that the current generation does not list, on each compaction pass. Before, it listed the files once, so a file left by a failed compaction install or by a second SharedWorker on the same database stayed on disk until the worker restarted.
- 83ce8e1: Every package now declares `sideEffects` in its `package.json`, so webpack and esbuild drop the modules an app does not import. With webpack, an app that imports only the error classes from `@opfs-lsm/kv` bundles 135 bytes brotli instead of 438, and no longer gets the SharedWorker chunk and the wasm file in its build output.
- a93f292: `update` acks about 40 µs sooner in Chrome. Its WAL transaction now commits as soon as the record is queued and no longer waits for the add's result to reach the tab. docstore `put`, `putMany` and `update` go through the same path.
